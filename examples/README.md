# Examples

## `w3c-bad-demo/` — evidence report from a live-site scan

A sample of the customer-facing evidence report that `a11ygate report` builds from `a11ygate scan` output.

| File | What it is |
| --- | --- |
| `w3c-bad-demo/scan.json` | The JSON written by `a11ygate scan`, unchanged. |
| `w3c-bad-demo/report.html` | Self-contained HTML report (inline CSS, no scripts or remote assets). Open it in a browser and print to PDF. |
| `w3c-bad-demo/report.md` | The same report as Markdown. |

### The site

The scan target is the "before" version of the W3C Web Accessibility Initiative's public [Before and After Demonstration](https://www.w3.org/WAI/demos/bad/) (BAD). W3C built and published this site with deliberate accessibility barriers to teach how to find and fix them, so it is a fair public target for a sample report. The findings describe that teaching demo and say nothing about W3C's own sites in general.

### How it was produced

The scan was run once, on 2026-11-12, with the source build of the CLI:

```bash
a11ygate scan https://www.w3.org/WAI/demos/bad/before/home.html --crawl 5
```

The scanner is read-only: it loaded at most 5 same-origin pages in headless Chromium with no login, form filling or clicks, honoured robots.txt, waited 1 second between page loads, and identified itself as A11yGate in the user agent. Because the crawl follows same-origin links, two of the five pages (`https://www.w3.org/` and `https://www.w3.org/WAI/`) are outside the demo itself. The report lists them, and the 188 links that were not followed, with the reason for each.

The reports were then generated offline from the saved JSON, with a fixed timestamp so they can be regenerated byte for byte:

```bash
npm run cli:build
node packages/cli/dist/cli.mjs report --scan examples/w3c-bad-demo/scan.json --generated-at 2026-11-12T13:00:00Z --out examples/w3c-bad-demo/report.html
node packages/cli/dist/cli.mjs report --scan examples/w3c-bad-demo/scan.json --generated-at 2026-11-12T13:00:00Z --out examples/w3c-bad-demo/report.md
```

No previous scan was given, so every finding is reported as new. Pass `--previous-scan <older scan.json>` to get the per-rule trend (new, fixed, still open).

Tests never fetch the site; they use the committed files only.

Automated testing only. Not a WCAG audit, certification or legal advice.
