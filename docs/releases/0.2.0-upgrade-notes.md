# Upgrade notes: published 0.1.0 → 0.2.0

These notes describe `main` at `a215b6f` (2026-11-14 10:59 Asia/Jerusalem) relative to the npm release `@qe-atlas/a11ygate@0.1.0` (2026-11-01). Package version is **0.2.0**. Intended npm dist-tag: `next` only. The `latest` tag stays 0.1.0 until a separate approval.

Automated testing only. Not a WCAG audit, certification or legal advice.

## Compatible as-is

- `npx @qe-atlas/a11ygate --current axe.json --baseline a11y/baseline.json` and `a11ygate ci` with the same flags still run the regression gate.
- Exit codes 0 / 1 / 2 have the same meaning.
- Node.js `>=20` is unchanged.
- The package still has no required runtime dependencies. An axe-only install (gate mode, no `scan`, no extra engines) does not pull Playwright, Lighthouse, HTML_CodeSniffer, or IBM Equal Access.
- `a11ygate [ci] --baseline <axe.json>` (the original axe JSON baseline) is unchanged. The new fingerprint baseline file from `a11ygate baseline create` is a separate format, used with `scan` and `report`.

## Additive commands and flags

- `a11ygate scan <url>` is new. It is **not** in published 0.1.0. To use it after 0.2.0: `npm install --save-dev playwright @axe-core/playwright && npx playwright install chromium`. Only scan sites you own or are authorized to test.
- `--format junit,sarif,json,md` and `--out-dir <dir>` are new on `ci` and `scan`. They do not change the exit code.
- `--engines` is opt-in and defaults to axe only. Extra engines need their optional peer packages.
- `a11ygate doctor` checks setup and exits 0 unless `--strict`.
- `a11ygate init` writes starter GitHub Actions or Jenkins config and does not overwrite existing files without `--force`.
- `a11ygate baseline create` records fingerprint baselines so `scan` can fail only on new findings.
- `a11ygate evidence pack` builds a zip of one scan's outputs plus a SHA-256 manifest.
- GitHub Action model-fix inputs stay **default off**. Enabling them requires configuration and, for live providers, secrets you add yourself. Draft fix PRs also need the repository setting "Allow GitHub Actions to create and approve pull requests".

## Report shape

JSON, Markdown, JUnit and SARIF reports may include additional fields (engines used/errored, attribution, coverage notes, fingerprints, `automationDetails`, repo-relative SARIF artifact paths). Existing fields used by 0.1.0 remain. Treat new fields as additive.

`releaseStatus` in JSON reports and evidence-pack manifests is `"released"` (it was `"unreleased-source-build"` in source builds after 0.1.0 and before this release).

SARIF intended for GitHub code scanning now uses repo-relative paths under `a11ygate-pages/` for page URLs, because GitHub rejects `https` artifact URIs. The real page URL is in the result message and in `properties.pageUrl`.
