### Upgrade notes

Everything below is opt-in or keeps existing output unless stated. Default axe-only runs without new flags produce the same reports as before. Behaviour changes to check when upgrading from a `main` build before these tasks:

- **`review` needs a terminal for interactive mode (A11Y-R51).** `a11ygate review <scan> --baseline <file>` without `--list` or `--group`, when stdin or stdout is not a TTY (CI, piped input), now exits 2 instead of silently printing the list and exiting 0. Pass `--list` in scripts. Ctrl+C or end of input mid-prompt now exits 130 (previously 2); the baseline is left unchanged either way.
- **HTML report v2 is the default (A11Y-R28).** Use `--report-version 1` for the previous HTML byte-for-byte.
- **`.a11ygate.yml` keys now apply at runtime (A11Y-R33).** Most keys were validated but ignored before. Precedence is CLI flag / Action input > `A11YGATE_*` environment variable > YAML > default; empty Action inputs now let repository settings apply. Check an existing file with `a11ygate config print` before upgrading.
- **Decision exports (A11Y-R43).** When a fingerprint baseline holds active `accepted-risk` or `false-positive` decisions, SARIF marks those results as accepted external suppressions, JUnit reports them as skipped cases, and GitLab Code Quality leaves them out of the main report and records them in `codequality-decided.json`. A CI dashboard that counts failures or Code Quality issues can therefore show fewer of them. Exports without decisions keep their bytes.
- **Baseline file fields.** Fingerprint baselines may now contain `groupDecisions` (A11Y-R39) and an append-only `history[]` (A11Y-R44). Older baselines without them still load; keep both fields when editing the file by hand.
- **Evidence-pack manifest fields (A11Y-R48).** Inside a git work tree, `manifest.json` records `commit.committedAt` and, when HEAD is the checked-out branch, `commit.branch`. `a11ygate trend` orders runs by commit time only when every pack records it, otherwise by scan time with a note; `--order scan|commit` overrides. Older packs still load.
- **EN 301 549 for WCAG 2.2-only criteria (A11Y-R59).** Scan JSON now has `en301549: null` (shown as "not in EN 301 549 V3.2.1") for 2.4.11, 2.5.7, 2.5.8, 3.2.6, 3.3.7 and 3.3.8 instead of a guessed clause such as `9.2.5.8`. Consumers that read that field must accept `null`.
- **Interaction states (A11Y-R45).** The default 20-state cap (`interactions.auto.maxStates`) also applies to legacy `--auto-interactions`, even when `--interaction-budget` is higher. The destructive-word rule also rejects explicit steps on buttons whose text matches (for example a `type=button` "Submit").
- **Lighthouse at concurrency above 1 (A11Y-R47).** Lighthouse snapshots are serialized behind a process-wide mutex, and scans that select Lighthouse log `lighthouse serialized` once. Other engines stay concurrent.
- **Explicit auth check (A11Y-R52).** When `auth.check` is configured it replaces heuristic login detection; failed checks skip engines and mark pages not authenticated. Without it the heuristic is unchanged.
- **Screenshots (A11Y-R50).** Screenshots stay off by default. `--no-screenshots` writes a `.a11ygate-no-screenshots` marker into the out dir, so later evidence packs from a reused out dir also exclude images.
- **Stricter malformed-input checks (A11Y-R61).** `.a11ygate.yml` refuses a `__proto__` key; evidence-pack zips with zip-slip names, duplicate, encrypted or ZIP64 entries, or entries declaring more than 64 MB are refused; `--storage-state` cookies with wrong field types fail before the browser starts. Each error names the file and the field.
- **Azure DevOps template (A11Y-R35).** The template uses `UseNode@1` instead of the deprecated Node.js tool installer v0 task (Microsoft marks v0 deprecated). Copies of the template made before this change still use the v0 task.

New opt-in commands and flags, all default off (see `a11ygate <command> --help`):

- `a11ygate review list|remove|prune` (A11Y-R44), `a11ygate report pdf` (A11Y-R53), `a11ygate export tickets` (A11Y-R54), `a11ygate estimate` (A11Y-R55), `a11ygate ci --projects` with `--parallel` and `a11ygate config validate --projects` (A11Y-R56), `a11ygate config print` (A11Y-R33), `a11ygate trend` (A11Y-R42) with `--order` (A11Y-R48).
- `scan`: `--incremental`, `--incremental-normalize` (A11Y-R60); `--changed-since`, `--routes` (A11Y-R57); `--keyboard`, `--keyboard-budget` (A11Y-R41) and `--keyboard-pixel-threshold` (A11Y-R46); `--screenshots`, `--no-screenshots`, `--redact-selector` (A11Y-R50); `--auth-check-url`, `--auth-check-must-have-selector`, `--auth-check-must-not-have-selector`, `--auth-check-must-not-redirect-to` (A11Y-R52); `--report-lang` (A11Y-R58); `--en301549-ref` (A11Y-R59); `--recycle-every` (A11Y-R38); `--interactions`, `--auto-interactions`, `--interaction-budget` (A11Y-R37); `--session-storage` (A11Y-R36); `--storage-state`, `--login-script`, `--login-timeout-ms`, `--cookie-env`, `--header-env` (A11Y-R27); `--start`, `--wait-on`, `--storybook` (A11Y-R26); `--sitemap`, `--include`, `--exclude`, `--max-pages`, `--max-depth`, `--timeout-ms`, `--concurrency`, `--ignore-robots` (A11Y-R30); `--report-version` (A11Y-R28).

### Added: scanning

- Crawler controls for customer sites: `--sitemap`, `--include` / `--exclude`, `--max-pages` (1–1000), `--max-depth`, `--timeout-ms`, `--concurrency`, `--ignore-robots`, retry-once navigation, same-origin checks on every redirect hop and skipped-page reasons in reports. `--crawl` keeps its 20-page cap (A11Y-R30, [#43](https://github.com/DaveEliranAssistant/a11ygate/pull/43)).
- Authenticated scans with Playwright storage state, a trusted login script, or cookies/headers referenced by environment variable name; login pages produce "Not authenticated" and exit 2, and credentials are redacted from every output (A11Y-R27, [#41](https://github.com/DaveEliranAssistant/a11ygate/pull/41)).
- sessionStorage authentication: login scripts capture it and `--session-storage <file>` restores it for the exact origin; values are never written back (A11Y-R36, [#53](https://github.com/DaveEliranAssistant/a11ygate/pull/53)).
- Explicit `auth.check` probe URL, required/forbidden selectors and forbidden redirect destination replace heuristic login detection when configured. Failed checks skip engines, mark pages not authenticated and count them separately; `doctor` warns when auth has no check. Default heuristic scans and report goldens are unchanged (A11Y-R52, [#61](https://github.com/DaveEliranAssistant/a11ygate/pull/61)).
- Opt-in SPA interaction states: `interactions` in YAML or `--interactions <file>` (click, press, wait), and `--auto-interactions` with `--interaction-budget` (A11Y-R37, [#55](https://github.com/DaveEliranAssistant/a11ygate/pull/55)).
- Opt-in `interactions.auto.depth` (default 1, maximum 3) and `maxStates` (default 20) explore newly revealed nested controls with path labels and clean route reloads. Legacy depth 1 labels remain unchanged; destructive-looking buttons are rejected using case-insensitive whole words, including child targets, while explicit container steps remain supported. The default 20-state cap also applies to legacy `--auto-interactions` even when `--interaction-budget` is higher (A11Y-R45, [#66](https://github.com/DaveEliranAssistant/a11ygate/pull/66)).
- Opt-in keyboard focus heuristics (`scan --keyboard`, `--keyboard-budget`): forward-Tab probe for focus visibility, traps, order and unreachable controls; every finding needs human review (A11Y-R41, [#56](https://github.com/DaveEliranAssistant/a11ygate/pull/56)).
- Opt-in keyboard checks traverse open shadow roots and same-origin frames, report cross-origin frames as not assessed, compare Shift+Tab order, probe roving-tabindex composites with arrow keys, detect cycles among 2–5 controls, and fall back to an in-memory focus pixel diff (`--keyboard-pixel-threshold`, default 0.01). Findings remain heuristics needing human review (A11Y-R46, [#75](https://github.com/DaveEliranAssistant/a11ygate/pull/75)).
- Opt-in masked viewport screenshots (`--screenshots`), default and custom `redact.selectors` overlays, and `--no-screenshots` capture/evidence exclusion. Doctor recommends disabling screenshots for auth scans (A11Y-R50, [#67](https://github.com/DaveEliranAssistant/a11ygate/pull/67)).
- Opt-in diff-aware PR scans (`scan --changed-since <ref>`, config `routes` / `changedSince`) select mapped URL paths from committed `<ref>...HEAD` changes. Unmapped files, shared `"*"` mappings or no changes retain the normal full scan. Reports record mode, reason and scanned/skipped routes; skipped baseline pages remain unassessed and review decisions still apply. No-flag report output is unchanged (A11Y-R57, [#76](https://github.com/DaveEliranAssistant/a11ygate/pull/76)).
- Opt-in `scan --incremental <cache-dir>` hashes rendered page/state DOM, normalizes volatile tokens with configurable regexes, and reuses successful engine findings only when DOM and engine/config compatibility match. Reports and evidence packs retain original scan IDs on cached pages. Corrupt cache data warns and forces a full rescan; default output is unchanged (A11Y-R60, [#77](https://github.com/DaveEliranAssistant/a11ygate/pull/77)).
- `a11ygate scan --recycle-every <n>` (config `recycleEvery`) opens a fresh browser context every n pages; retired contexts close only after their in-flight pages finish. Opt-in: without it the scan keeps one context, as before. `npm run bench` (not part of `npm test` or CI) records peak RSS, pages per minute and failures against a generated loopback fixture; recorded results and the sizing table are in `docs/perf/` (A11Y-R38, [#54](https://github.com/DaveEliranAssistant/a11ygate/pull/54)).
- Benchmark v2: `npm run bench` now samples peak RSS of the whole process tree (the Node CLI plus every Chromium descendant, every 250 ms with `ps`, same columns on macOS and Linux), caps each run with `npm run bench -- --max-run-ms <ms>` and records a run that hits the cap as "not completed" with no throughput figure, can refuse to start runs after a time with `npm run bench -- --no-new-cell-after <time>`, and saves results after every run. Recorded on the Mac: 500 pages × {axe, all engines} × concurrency {1, 2, 4} in [docs/perf/bench-v2.md](../../docs/perf/bench-v2.md), with the sizing table updated. Not part of `npm test` or CI (A11Y-R49, [#79](https://github.com/DaveEliranAssistant/a11ygate/pull/79)).

### Added: reports and exports

- `a11ygate pilot report` compares kickoff and latest evidence packs, evaluates recorded pilot criteria, and writes local HTML and PDF results and a draft renewal quote (A11Y-R69). See the [pilot closeout guide](../../docs/pilot/README.md#close-out-a-pilot).

- `a11ygate prospect <url|scan-dir>` and `prospect --from <scan-out-dir>` write a short HTML and PDF summary with prioritized issues, CI guidance, and a scope manifest. Third-party URL scans require recorded authorization. `--offer` includes the price and pilot from the billing config (A11Y-R67).

- Likely shared components: repeated template findings are grouped across pages in HTML report v2, JSON and SARIF related locations. Totals and gate results are unchanged; groups are heuristics needing human review (A11Y-R29, [#45](https://github.com/DaveEliranAssistant/a11ygate/pull/45)).
- Report strings for HTML report v2 and the Markdown / CLI summary now come from a message catalog (`locales/en.json`, `{var}` format). `a11ygate scan --report-lang en` is the default and only shipped language; the output is byte-identical to before. The pseudo-locales `en-XA` (accented, expanded) and `ar-XB` (right-to-left, `dir="rtl"`) are for layout testing only. The disclaimer and legal wording are never translated. See `docs/report-locales.md` for how a human translator adds a locale (A11Y-R58, [#70](https://github.com/DaveEliranAssistant/a11ygate/pull/70)).
- `a11ygate scan --en301549-ref` adds an opt-in "EN 301 549 ref." column, labelled "Reference mapping only; does not indicate conformance.", to HTML report v2 and SARIF rule properties; the web app adds a CSV export with the same column. The mapping table cites ETSI EN 301 549 V3.2.1 clause 9. Default off; output without the flag is unchanged (A11Y-R59, [#60](https://github.com/DaveEliranAssistant/a11ygate/pull/60)).
- `a11ygate report pdf <scan.json|out-dir> [-o report.pdf] [--commit <sha>]` prints HTML report v2 to PDF with the local Playwright Chromium (`page.pdf`): a cover page (site, scan date, commit, engines, scope), a table of contents with page numbers, page numbers and the disclaimer in the footer of every page. Text stays selectable; the PDF is tagged (Chromium `tagged: true`) with an outline, and its title and language are set from the report. Output is deterministic apart from the PDF creation timestamps. New cover/TOC/footer strings are in `locales/en.json`; the disclaimer is verbatim from `lib/copy.ts`. Existing report outputs are unchanged (A11Y-R53, [#73](https://github.com/DaveEliranAssistant/a11ygate/pull/73)).
- `a11ygate export tickets <scan.json|out-dir> --format csv|jira-csv|gh-md [--baseline <file>] [--output <file>]` exports developer handoff tickets: one per likely shared component group or per ungrouped finding, skipping active accepted-risk/false-positive decisions (expired decisions stay open). Fields: title, WCAG SC, EN 301 549 ref. (reference mapping only; does not indicate conformance), impact, pages affected (count and first 5 URLs), selector, snippet, how-to-fix link and a stable `a11ygate-g-…` fingerprint. Jira CSV follows Atlassian's CSV import headers. Export only: no Jira or GitHub API calls (A11Y-R54, [#72](https://github.com/DaveEliranAssistant/a11ygate/pull/72)).
- `a11ygate estimate <url>` adds a bounded crawl-only pilot scope report (Markdown + JSON): sitemap/crawl union, likely numeric/UUID URL templates, login/SPA signals, robots exclusions, and scan-time extrapolation quoting successful recorded benchmark rows. No engines, model or pricing; static HTML limitations are explicit (A11Y-R55, [#71](https://github.com/DaveEliranAssistant/a11ygate/pull/71)).

### Added: review decisions

- `a11ygate review <scan> --baseline <file>` records one reviewer decision per likely shared component group: `to-fix`, `accepted-risk` (reason required, optional `--expires YYYY-MM-DD`) or `false-positive` (reason required). Non-interactive flags (`--list`, `--group`, `--decision`, `--reason`, `--expires`) or an interactive TTY prompt. Decisions are stored under `groupDecisions` in the fingerprint baseline with the reviewer from `git config user.name` and the date. Matching findings on new pages inherit the decision; expired accepted-risk decisions gate again. Decided findings stay listed and get a "Review decisions" report section. Baselines without decisions produce unchanged output (A11Y-R39, [#57](https://github.com/DaveEliranAssistant/a11ygate/pull/57)).
- `a11ygate review list [--status <kind>] [--expired] [--json]`, `review remove <group-id|--all-expired>` (needs `--yes` or a terminal confirmation) and `review prune <scan> [--dry-run]` (removes decisions whose group has no finding in the latest scan) manage recorded decisions. Every baseline change, including recording a decision, is written atomically (temp file + rename) and appends to an append-only `history[]` with who (`git config user.name`, else "unknown" for remove/prune), when, the action and the earlier decision. Baselines without `history` still load; report output is unchanged (A11Y-R44, [#69](https://github.com/DaveEliranAssistant/a11ygate/pull/69)).

### Added: configuration, evidence and diagnostics

- `schema/a11ygate.schema.json` describes `.a11ygate.yml` (url, crawl, failOn, engines, modelFixes, baseline, formats, outDir, delayMs, reportVersion, auth). `a11ygate config validate [file]` and a new `doctor` config check report plain-English errors such as "unknown key 'engine' — did you mean 'engines'?". `a11ygate init` adds a `# yaml-language-server: $schema=` line for editor autocomplete (A11Y-R31, [#42](https://github.com/DaveEliranAssistant/a11ygate/pull/42)).
- `.a11ygate.yml` settings apply across `scan`, `ci`, `doctor` and the Action through one resolver (flag > environment > YAML > default); `a11ygate config print [scan|ci|doctor]` shows effective values and their sources with credentials redacted (A11Y-R33, [#50](https://github.com/DaveEliranAssistant/a11ygate/pull/50)).
- `a11ygate trend <dir-of-evidence-packs>` writes JSON and a script-free HTML history: findings per run, top rules over time and pages with the most regressions (A11Y-R42, [#58](https://github.com/DaveEliranAssistant/a11ygate/pull/58)).
- `a11ygate evidence pack` records `commit.committedAt` (from `git log -1 --format=%cI`) and `commit.branch` (when the commit is the checked-out branch HEAD) in `manifest.json` when run inside a git work tree; nothing is recorded otherwise. `a11ygate trend` orders runs by commit time when every pack records it, otherwise by scan time with a visible note, and takes `--order scan|commit`. Packs made before this change still load (A11Y-R48, [#63](https://github.com/DaveEliranAssistant/a11ygate/pull/63)).
- `--debug` (or `A11YGATE_DEBUG=1`) on any command prints the stack trace (and cause chain) of an unexpected error and of input/setup errors that commands report themselves, such as a malformed `--storage-state`, baseline or interactions file; by default only the message is shown (A11Y-R61, [#62](https://github.com/DaveEliranAssistant/a11ygate/pull/62)).

### Changed

- `a11ygate review <scan> --baseline <file>` without `--list` or `--group` now needs a terminal: when stdin or stdout is not a TTY (CI, piped input) it exits 2 with "interactive review needs a terminal …" and points to `--list` / `--group`, instead of silently falling back to the list. Pass `--list` for the previous output. In the interactive prompt, `[r] remove decision` removes a group's existing decision (recorded in `history[]` like `review remove`), and Ctrl+C or end of input mid-prompt now exits 130 with "Review interrupted. Nothing was written to the baseline." instead of "Could not record review: Aborted with Ctrl+C" (exit 2); the baseline was and is left byte-identical. Covered by a pseudo-TTY test of the built CLI using the optional `node-pty` dependency (skipped with a note when it cannot load) (A11Y-R51, [#74](https://github.com/DaveEliranAssistant/a11ygate/pull/74)).
- Review decisions now reach SARIF (accepted external suppressions), JUnit (skipped cases), and GitLab Code Quality (active exclusions recorded in `codequality-decided.json`). To-fix and expired decisions remain normal findings; exports without decisions retain their existing bytes (A11Y-R43, [#59](https://github.com/DaveEliranAssistant/a11ygate/pull/59)).
- WCAG 2.2-only success criteria (2.4.11, 2.5.7, 2.5.8, 3.2.6, 3.3.7, 3.3.8) no longer get a guessed EN 301 549 clause such as `9.2.5.8`. They now read "not in EN 301 549 V3.2.1" in standards labels and `en301549: null` in scan JSON (A11Y-R59, [#60](https://github.com/DaveEliranAssistant/a11ygate/pull/60)).
- Lighthouse snapshots now use a process-wide mutex to avoid shared timing-mark collisions at scan concurrency greater than 1. Other engines and page loading keep their existing concurrency; scans selecting Lighthouse log `lighthouse serialized` once (A11Y-R47, [#64](https://github.com/DaveEliranAssistant/a11ygate/pull/64)).
- `a11ygate scan` HTML report v2 is the default: executive summary (pages, totals, new vs baseline, engines used/errored), top 10 fixes ordered by impact × pages affected, findings grouped by WCAG success criterion and by page, per-rule how-to-fix with links taken only from the finding's engine help URL and the W3C Understanding table in `lib/mapping.ts`, a "what automated testing does not cover" section, print CSS and a contrast-tested dark scheme. `--report-version 1` emits the previous HTML byte-for-byte (A11Y-R28, [#40](https://github.com/DaveEliranAssistant/a11ygate/pull/40)).
- The Azure DevOps template installs Node.js with `UseNode@1` instead of the deprecated v0 task; the version is always passed explicitly (A11Y-R35, [#49](https://github.com/DaveEliranAssistant/a11ygate/pull/49)).

### Fixed

- Reverse keyboard traversal skips opaque cross-origin frame focus stops, matching the candidate-only forward order without reporting a false reverse-order finding. Unexpected document boundaries still count as mismatches; exhausting the budget within a frame does not (A11Y-R46 review, [#75](https://github.com/DaveEliranAssistant/a11ygate/pull/75)).
- Malformed input hardening, found by new fast-check property tests (A11Y-R61, [#62](https://github.com/DaveEliranAssistant/a11ygate/pull/62)): `.a11ygate.yml` refuses a `__proto__` key (it previously changed the parsed object's prototype, so nested values skipped validation); evidence-pack zip reading bounds-checks every offset (corrupt zips raised a raw `RangeError`), refuses zip-slip names, duplicate, encrypted and ZIP64 entries, and rejects entries declaring more than 64 MB before inflating; `a11ygate trend` skips packs whose manifest or scan report has wrong field types instead of crashing; baseline, interactions, `--storage-state` and `--session-storage` errors now name the file and the field; `--storage-state` cookies are checked for a string `url` or `domain`/`path` pair, numeric `expires`, boolean `httpOnly`/`secure` and `sameSite` of Strict/Lax/None before the browser starts (previously Playwright rejected them later with a generic message) (for example `findings[0].selector`) without echoing values; `a11ygate review` writes the baseline via a temp file and rename. Every malformed-input error now names the file and the field: evidence-pack manifests (`commit.sha`, `files[i].sha256`, `timestamps.scannedAt`, …) and scan reports (`counts.pagesScanned`, `findings[i].wcag`, …) in `a11ygate trend`, `.a11ygate.yml` (line and key), the interactions file (`interactions[i].route`, `steps[j].key`, …; `--interactions <file>` no longer hides the reason) and top-level shape errors in the baseline and storage files. A scan report with a `null` WCAG entry no longer crashes fingerprinting with a `TypeError`.

## [0.2.0] — 2026-11-14 (npm `next` only; `latest` unchanged)

### Added

- `a11ygate scan`: live-site scan with a same-origin crawl (hard cap 20 pages). Optional peers: `playwright` and `@axe-core/playwright`. Not present in published 0.1.0 (scan work, #12).
- `--format` / `--out-dir` on `ci` and `scan`: JUnit XML (Jenkins) and SARIF 2.1.0 (GitHub code scanning), plus JSON/Markdown (A11Y-R7, #18).
- SARIF output honours GitHub code scanning limits, emits a stable `partialFingerprints.primaryLocationLineHash`, sets `automationDetails.id` per engine (`a11ygate/<engine>/`), and rewrites page URLs to repo-relative artifact paths so `upload-sarif` is accepted (A11Y-R15, #29). Example workflow: `examples/github-code-scanning/sarif.yml`.
- Jenkins shared library step and example `Jenkinsfile`s, plus an integration guide (A11Y-R8/R9, #20/#23). A real Dockerized Jenkins acceptance job now runs in CI (A11Y-R16, #30).
- Opt-in scan engines (HTML_CodeSniffer, IBM Equal Access, Lighthouse) behind `--engines`. Default remains axe only (A11Y-R10/R11, #17/#22). Cross-engine dedupe and attribution in reports (A11Y-R12, #25).
- Optional, default-off model-assisted fix drafts (A11Y-R1–R6, #19/#21/#24/#26/#27/#28): orchestrator with exact F1 fallback, strict draft validator, isolated verifier, draft-only publisher, free-tier provider adapters (Groq, Gemini, Cloudflare), Action wiring. Requires explicit opt-in. CI uses stubs only. No API keys are shipped in the package.
- Manual, secret-gated live provider smoke workflow (`workflow_dispatch` only). Secrets are not in the package; do not add keys unattended (A11Y-R17, #33).
- Coverage-aware regression evidence and reviewable findings in the gate reports (#6).
- Rule-based GitHub suggested changes for a small set of common axe findings (F1, #15).
- GitHub Action setup requirements: required permissions, PR head-SHA checkout, fork limits, and the "Allow GitHub Actions to create and approve pull requests" setting for draft fix PRs (A11Y-R13, #31).
- `a11ygate doctor`: preflight checks (checkout SHA, permissions, Chromium, Node, optional engine peers, model-fix config). Does not fail a build unless `--strict` (A11Y-R14, #36).
- Fingerprint baselines: `a11ygate baseline create` and `scan`/`report --baseline` so a legacy site can fail only on new findings. The existing `a11ygate [ci] --baseline <axe.json>` format is unchanged (A11Y-R18, #35).
- `a11ygate init`: writes `.a11ygate.yml` and a GitHub Actions workflow or Jenkinsfile (`--yes` for non-interactive use). Does not overwrite existing files without `--force` (A11Y-R19, #37).
- `a11ygate evidence pack`: one zip per scan (HTML/MD, SARIF, JUnit, raw engine JSON, screenshots if present, and a SHA-256 manifest). The front page states what automated testing cannot cover, plus the disclaimer (A11Y-R20, #34).

### Changed

- CLI README documents the new subcommands, formats, Jenkins, GitHub code scanning, and optional engines. Gate usage (`a11ygate ci` / default command) is unchanged: it still fails only on **new** findings at or above the impact threshold when using axe JSON baselines.
- Optional engine peer dependencies are declared as optional peers. An axe-only / gate-only install does not need them.
- `a11ygate --help` no longer calls this a source-only unreleased build. JSON and evidence-pack manifests use `releaseStatus: "released"` instead of `"unreleased-source-build"`.

### Upgrade notes (from published 0.1.0)

See [upgrade notes](../../docs/releases/0.2.0-upgrade-notes.md). In short: existing `a11ygate --current … --baseline …` invocations keep working. New subcommands and flags are additive. `scan` and extra engines need their optional peers. Model-fix features stay off unless enabled. Node.js `>=20` is unchanged.
